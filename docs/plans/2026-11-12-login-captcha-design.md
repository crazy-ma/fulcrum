# 登录图形验证码与安全日志设计

**日期：** 2026-11-12

**状态：** 已确认，进入实现计划

## 目标

为企业账号 `/login` 和平台管理员 `/platform/login` 增加强制图形验证码，阻断自动化登录脚本的直接撞库；复用现有 PNG 验证码生成器，保证验证码挑战只能消费一次，同时不为每次攻击请求写入数据库。登录与验证码安全事件通过现有平台全局日志查看。

## 现状与根因

- `app/services/image_captcha.py` 已经能够生成带 HMAC 签名的短时 PNG 验证码，但当前只用于 `/register`。
- `/login` 和 `/platform/login` 只接收账号与密码，没有验证码字段，也没有登录安全事件日志。
- 现有验证码令牌是无状态校验；如果直接复用到登录，令牌在有效期内可以重复提交，不能满足一次性挑战要求。
- 平台运维的 `/platform/logs` 已经读取 `app.log` 和 `error.log`，但目前只能看到通用的请求完成记录。

## 设计选择

### 验证码挑战

不新增验证码数据库表，也不把挑战写入现有业务表。验证码服务维护一个进程内有界注册表：

- 注册表只保存令牌摘要和过期时间，不保存答案明文、图片或原始令牌。
- 签发时写入注册表，消费时在锁内校验并移除；错误答案、过期挑战、重复提交都视为消费失败。
- 每次操作先清理过期项，再按固定容量淘汰最旧项，容量和 TTL 由设置项控制，避免攻击请求造成无界内存增长。
- 注册、企业登录、平台登录共用同一套签发与消费路径，只通过用途值区分，不能跨用途复用令牌。
- 当前启动脚本使用单个 Uvicorn 进程，进程内注册表与现有部署一致；未来若改为多进程或多副本，需要把注册表替换为共享 Redis 等外部短时存储，不能把本地缓存误认为跨进程的一次性保证。

### 登录请求流

1. 登录 GET 与注册 GET 签发新的验证码挑战，并把图片和隐藏令牌交给模板。
2. 登录 POST 先消费对应用途的验证码挑战；缺失、错误、过期和重复使用统一返回验证码错误。
3. 验证码通过后，继续执行现有 Argon2 密码认证、会话创建和原有跳转。
4. 密码错误沿用现有统一错误提示，并重新渲染新挑战；不增加数据库失败计数。
5. 登录成功只保留现有会话表写入，不为验证码或失败尝试新增数据库记录。

本次不加入数据库失败节流。验证码提高单次自动化尝试成本，后续如需进一步限制 Argon2 计算压力，应另行评估共享内存限流或 Redis，而不是记录逐次失败行。

### 页面交互

- 企业登录和平台登录都在首屏显示验证码输入框、图片和“换一张”操作。
- 刷新只重新获取当前入口页面，不改变账号字段和认证入口。
- 验证码输入使用数字键盘语义、`autocomplete="off"` 和长度限制；图片提供描述文本。
- 账号字段失败时只回填手机号或用户名，密码和验证码答案不回填。

### 安全日志

认证路由使用现有应用 logger 写结构化事件，平台运维通过 `/platform/logs` 的全局日志页筛选：

- `login captcha rejected`：验证码缺失、错误、过期或重复使用。
- `login credentials rejected`：验证码通过但账号密码失败。
- `login succeeded`：登录成功。

事件字段固定为 `auth_scope`、`reason`、`identity_hint`、`client_ip`。`identity_hint` 只保留脱敏手机号或用户名，原始密码、验证码答案、验证码令牌、会话令牌不进入日志。日志解析器增加对应的中文标题和字段名称，保持现有日志文件格式与轮转策略。

## 错误边界

- 验证码服务对畸形令牌、签名不匹配、用途不匹配、过期和重复消费统一返回失败，不把内部异常返回给浏览器。
- 验证码失败使用 HTTP 400；密码失败使用现有 HTTP 401；成功跳转和会话 Cookie 行为保持不变。
- 认证失败日志不区分“账号不存在”和“密码错误”，避免账号枚举。
- 有界缓存满时淘汰最早挑战；被淘汰的表单按过期挑战处理，用户重新换图即可。
- 日志写入失败不能阻断登录主流程；日志记录异常只写应用错误日志，不回滚已有会话行为。

## 代码范围

- `app/services/image_captcha.py`：增加用途绑定、有界一次性挑战注册表和消费接口。
- `app/web/public_site.py`：企业登录与注册接入挑战签发、消费和认证事件日志。
- `app/web/platform_auth.py`：平台登录接入挑战签发、消费和认证事件日志。
- `app/templates/_auth_fields.html`、`enterprise_login.html`、`platform_login.html`：增加共享验证码字段与换图控件。
- `app/static/js/auth.js`、`app/static/css/style.css`：实现换图交互和认证页验证码布局。
- `app/services/log_view.py`：增加安全事件中文标题和字段标签。
- `app/core/settings.py`：增加有界缓存容量、TTL 等可调设置。
- `tests/test_public_site_auth.py`、`tests/test_saas_login.py` 及必要的新测试：覆盖服务、路由、日志和缓存淘汰。

本次不新增 Alembic 迁移、不新增数据库模型、不修改会话表结构、不保留旧登录兼容入口。

## 验证策略

只执行与本次改动直接相关的轻量验证：

- 验证码服务定向单元测试：正确答案、错误答案、签名篡改、用途不匹配、过期、重复消费和容量淘汰。
- 企业与平台登录定向路由测试：GET 展示挑战、POST 必须提交挑战、正确挑战成功登录、失败后刷新挑战、旧挑战不能重放。
- 日志测试：认证事件包含安全字段和脱敏身份，不包含密码、答案或令牌；平台日志解析显示中文标题。
- `python -m compileall`、`git diff --check` 和定向 pytest；不把全量回归或多进程部署验收表述为已完成。
